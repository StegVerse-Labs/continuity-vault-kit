# Multi-Session AI Collaboration Example

Use this packet when several AI sessions or tools contribute to one project.

## Shared objective

Produce a reviewed project plan without allowing any session to treat its own output as final authority.

## Session register

| Session | Contribution | Evidence used | Status |
|---|---|---|---|
| A | Drafted requirements | Owner notes | Proposal |
| B | Checked internal consistency | Requirements draft | Review |
| C | Identified missing risks | Draft and source records | Review |

## Accepted state

- The owner approved the project objective.
- Source records are listed in the project index.
- No implementation change has been authorized.

## Proposed state

- Session A proposed a milestone order.
- Session B proposed wording changes.
- Session C proposed additional risk controls.

Proposals remain separate from accepted decisions.

## Conflicts

- Sessions A and C assign different priority to one milestone.
- Session B assumed a dependency that is not present in the source records.

## Authority boundary

A later session may summarize, compare, and identify conflicts. It may not merge proposals into the accepted state unless the designated owner or durable policy grants that action.

## Next permitted action

Present the conflicting milestone priorities and unsupported dependency to the owner for resolution. Record the decision and its source before continuing implementation.
